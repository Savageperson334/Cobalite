# Voice Society / Chord Memory — 0.6 experiment

## Voice Society
Eight permanent voice slots, each with deterministic colour, pan, motion phase, detune and attack traits. Note allocation is separate from synthesis so the same event contract can eventually drive Living Circuits or embedded code. The allocator emits start/release/clear messages carrying slot index, generation, pitch, velocity, group role, gain and whether a voice was stolen. A renderer reports completed releases with the generation to avoid freeing a reused slot.

Modes: Poly (8 independent notes), Mono (last-note priority and fallback; overlapping release tails), Unison 2/4/8, Stack 2 (octave), Stack 4 (root/fifth/octave/twelfth), Complement (paired contrasting timbres). All share the eight-slot budget. Allocation prefers free slots, then released slots, then oldest active slots; stealing an active multi-voice group releases its remaining slots. The audition renderer approximates a stolen note's fade with its last sample and a 2 ms time constant, not a complete old-voice render. Mode changes clear notes. Panic clears all active audio, not persistent voice traits.

Individuality blends per-voice differences into tone, attack, stereo and subtle pitch variation; Cohesion balances shared and independent slow motion; History accumulates on assignment and decays with a 25-second time constant, even in silence. History currently brightens/warms the harmonic mixture rather than storing note pitches. Classic, Living and Swarm buttons provide starting points. Mono glide is optional, with retriggered envelope rather than true legato; this is not the final voice engine.

## Chord Memory
Capture notes together or individually, finish to store up to eight distinct notes as intervals relative to the lowest note. The interface enables chord playback after a successful capture. A root key transposes the stored voicing. Inversion moves pitches by octaves; Spread creates wider voicings using octave displacement; notes beyond MIDI range are omitted rather than clamped. The original interval list remains unchanged. A simple arpeggiator plays the captured voicing up, down, pendulum or outside-in using the audio sample clock, internal BPM, subdivision and gate. The most recently held root controls the arp; releasing the last root releases its notes immediately. Voicing edits affect the next trigger, not held notes. Normal mode disables the chord transform. The eight-voice pool is shared: large chords combined with multi-voice unison/stack may steal notes, so Poly is the recommended chord mode.

## Audition
Serve prototype/ as before, open society.html, enable audio at low volume. Try Classic/Living/Swarm with the same chord; play repeated notes to see slot history; compare Unison 2 and Complement. Capture an unusual voicing (for example C E G B), finish, then play single root keys; try inversion/spread and arp. MIDI note/velocity/sustain and computer keys are supported.

## Integration contract
The standalone allocator is a candidate for a unified instrument: incoming live notes, phrase events and chord-expanded notes should have unique IDs and one shared allocator. Transform ordering: physical note -> chord/arp (optional) -> voice pool; recorded phrase input should explicitly select raw input vs generated output to avoid double-expanding notes. Per-voice state belongs to slot identity, global modulation remains global unless the destination is per-voice. Keep independent envelopes and LFO phase in renderer state. Expose note count and playing history as bounded modulation sources. Do not add a voice-mode menu per subsystem. Real panel mapping should use one local voice context; chord capture reuses the capture grammar, not global Shift.

## Limitations
Independent audition synth, no integration with Living Circuits, Phrase Ecology or actual firmware. No external clock, pitch bend, MPE, note-priority options, true legato, persistent chord banks or physical panel simulator yet. Browser/MIDI interaction and listening quality remain untested. Allocation is event-driven and not yet proven on target hardware. Headless tests passed at 44.1 and 48 kHz for all mode allocation counts, mono fallback, atomic stealing, chord transposition and pitch-class preservation, arp order and stop, release and finite bounded audio. Run node prototype/society-test.cjs. A first-note arp startup bug was found during testing and corrected.
